## 审核方法

1. 阅读 [README.md](../README.md) 的适用范围和风险声明。
2. 对照 [REFERENCES.md](../REFERENCES.md) 查看 12 项清单的证据来源和限制。
3. 仅使用虚构场景或不含患者信息的抽象工作流程测试页面。
4. 对每一项选择：保留 / 修改 / 删除 / 无法判断。
5. 将建议写成可执行的措辞修改，并说明理由。
6. 不把本工具当作诊疗规范、给药建议或出院决策工具。

## 总体审核问题

- [ ] 清楚说明本工具只检查记录完整性，不提供诊断或治疗建议。
- [ ] 清楚说明不能录入患者身份信息。
- [ ] 清单顺序适合急诊处置后进行病历复核。
- [ ] 没有措辞会被误解为强制治疗、固定剂量或固定留观时长。
- [ ] 关键阴性体征的提示不会被误解为排除过敏性休克的依据。
- [ ] 国际指南与本地规范之间的适用边界表达清楚。
- [ ] 页面在手机与常用电脑上易读、易点选。
- [ ] 复制出的摘要不会自动包含患者信息。

## 需要特别回答的问题

1. 是否缺少任何对病历完整性至关重要的记录项？
2. 哪些文字可能被误解为治疗建议或诊断标准？
3. 哪些项目在基层急诊实际工作中难以执行或记录？
4. 哪些项目应根据中国现行指南、本地制度或转诊条件调整？
5. 哪些提示应移到“必须记录”“建议记录”或“处置后复评”的其他分组？
6. 现有安全声明是否足以阻止超范围使用？

## 审核结论

选择一项：

- [ ] 可按当前原型继续公开测试；仍不得替代本地制度或临床判断。
- [ ] 修改后可继续公开测试；修改项见上表。
- [ ] 存在重大风险，修改前应停止面向临床人员试用。
- [ ] 证据或专业范围不足，无法给出结论。

## 完成标准

Issue #2 只有在以下条件全部满足后才能关闭：

- 至少两名基层、全科或急诊临床医生完成独立审核；
- 审核人的资质已由维护者核验；
- 仓库仅公开去标识化意见；
- 接受的修改均链接到 Issue、PR 或提交；
- 分歧意见和处理理由有记录；
- 未声称审核等同于机构认证、指南背书或医疗器械验证。
